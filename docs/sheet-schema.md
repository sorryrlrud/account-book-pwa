# Sheet schema guide

이 문서는 SRS v1.0 기준으로 앱이 기대하는 Google Spreadsheet 구조를 정리합니다.

## Core principles

- Source of Truth는 월별 원본 시트 `1`~`12`이다.
- `0` 시트는 전년도 12월 snapshot이다.
- 앱은 원본 월 시트를 읽고 쓴다.
- `통합` 시트가 있더라도 read-only view로만 취급한다.
- 기존 우측 수식/집계 영역은 초기 마이그레이션에서 보존한다.

`투자`, `에너지` 탭 구조가 맞지 않더라도 핵심 거래 기능은 계속 동작해야 합니다.

## 앱설정

권장 구조:

| key | value |
| --- | --- |
| year | 2026 |
| schemaVersion | 1 |
| environment | TEST |
| previousSpreadsheetId |  |
| nextSpreadsheetId |  |
| createdAt | 2026-08-10T00:00:00+09:00 |
| updatedAt | 2026-08-10T00:00:00+09:00 |

필수 규칙:

- `A1:B1`은 각각 `key`, `value` 헤더이며 실제 설정값은 2행부터 시작
- `schemaVersion`은 `1`
- `year`는 Spreadsheet 연도와 일치
- 현재 연결된 사본은 식별을 위해 `environment = TEST`를 유지한다.
- `environment` 값은 설명용 메타데이터이며 write 허용 여부를 결정하지 않는다.
- 이전/다음 연도 연결은 이 탭을 통해 추적

## Month sheets

월별 거래 원본은 각 월 탭에 append됩니다.

핵심 사용자 컬럼:

| Column | Meaning |
| --- | --- |
| A | 날짜 |
| B | 금액 |
| C | 내용 |
| D | 통장 |
| E | 분류 |

앱 메타데이터 권장 hidden 컬럼:

| Column | Meaning |
| --- | --- |
| X | 거래유형 |
| Y | 거래ID |
| Z | 이체ID |

규칙:

- 사용자가 Sheet에서 A:E만 직접 입력해도 앱은 읽어야 한다.
- 앱은 F열 및 기존 우측 집계 수식에 의존하지 않는다.
- 앱 생성 거래는 가능한 경우 X:Z metadata를 반드시 기록한다.

`0` 탭의 앱용 연도 시작잔액 Snapshot:

| Column | Meaning |
| --- | --- |
| AB | 통장 |
| AC | 연도시작잔액 |

- `AB1:AC1` 헤더는 `통장`, `연도시작잔액`을 사용한다.
- 최초 TEST 연도는 기존 원장의 전년도 말 잔액을 이 영역에 한 번 비파괴적으로 입력한다.
- 이후 `0월 데이터 업데이트`가 전년도 12월 말 계산 잔액으로 이 영역을 갱신한다.
- A:Z의 전년도 12월 Snapshot과 기존 우측 수식 영역은 그대로 보존한다.

## 거래 유형과 금액 규칙

- 지출: 음수 저장
- 수입: 양수 저장
- 이체: 두 행으로 저장

예시:

```text
지출 24000 -> -24000
수입 5900000 -> +5900000
이체 1000000 ->
  -1000000 | 생활비 이동 | 토스
  +1000000 | 생활비 이동 | 파킹
```

## 통장 master

탭 이름: `통장`

권장 구조:

| 통장 | 사용 | 자산그룹 | 순서 |
| --- | --- | --- | --- |
| 토스 | TRUE | 현금성 | 1 |
| 파킹 | TRUE | 현금성 | 2 |
| 네페 | TRUE | 결제 | 3 |
| 현카 | TRUE | 신용카드 | 4 |

규칙:

- `사용=TRUE`만 신규 입력 dropdown에 표시
- `사용=FALSE`라도 기존 거래에서는 정상 표시
- 이름 변경 시 현재 연도 `1`~`12` 거래의 해당 이름도 함께 변경

## 카테고리 master

탭 이름: `카테고리`

권장 구조:

| 카테고리 | 사용 | 예산그룹 | 순서 |
| --- | --- | --- | --- |
| 식비 | TRUE | 생활비 | 1 |
| 생활 | TRUE | 생활비 | 2 |
| 관리 | TRUE | 생활비 | 3 |
| 고냥 | TRUE | 반려동물 | 4 |

규칙:

- 계층 구조를 만들지 않는다.
- 카테고리는 최대 하나의 예산그룹에만 속한다.
- 사용 중지된 카테고리는 신규 입력에서 숨기되 기존 거래 표시는 유지한다.

## 예산그룹

탭 이름: `예산그룹`

권장 구조:

| 예산그룹 | 기준월예산 | 사용 | 순서 |
| --- | --- | --- | --- |
| 생활비 | 1500000 | TRUE | 1 |
| 반려동물 | 500000 | TRUE | 2 |

관리 규칙:

- 기준 월예산은 이후 새로 생성되는 `예산월별` 행의 snapshot 원본이다.
- 앱 설정에서는 예산그룹을 추가할 수 있지만 기존 기준 월예산은 편집하지 않는다.
- 기본값 변경은 Sheet의 `예산그룹.기준월예산`, 이미 생성된 월의 변경은 `예산월별.기준예산Snapshot`에서 직접 수행한다.
- 앱은 예산 화면을 다시 열거나 브라우저 포커스가 돌아오면 Sheet 값을 다시 읽어 변경 내용을 반영한다.

## 예산월별

탭 이름: `예산월별`

원본 필드:

| 월 | 예산그룹 | 할당예산Snapshot | 레거시조정 |
| --- | --- | --- | --- |
| 0 | 생활비 | 전년도 12월 잔여 | 0 |
| 1 | 생활비 | 1500000 | 0 |
| 1 | __MONTHLY_BUDGET_LIMIT__ | 2500000 | 0 |
| 2 | 생활비 | 1500000 | 0 |

계산 필드:

- 전월이월
- 실제예산
- 사용액
- 잔여
- 다음달예상

규칙:

- 월·예산그룹 행은 예산 편집 내용을 처음 저장할 때 앱이 자동으로 생성한다.
- 행이 아직 없으면 조회 시 `예산그룹.기준월예산`을 할당 예산으로 사용한다.
- `__MONTHLY_BUDGET_LIMIT__` 시스템 행의 `할당예산Snapshot`은 이월을 제외한 해당 월의 최대 예산이다. 시스템 행이 없는 기존 월은 활성 예산그룹의 할당액 합계를 최대 예산으로 간주한다.
- 예산 편집 저장 시 각 그룹의 `할당예산Snapshot`을 교체하고 `레거시조정`을 `0`으로 정리한다.
- 기존 `수동조정` 값이 남은 행은 `기준예산Snapshot + 수동조정`을 할당 예산으로 계산해 기존 금액을 보존한다.
- 같은 월·예산그룹 행이 중복되면 모호한 예산 쓰기를 거부한다.
- 1월 전월이월은 `0`월 snapshot의 예산 잔여를 사용
- `0월 데이터 업데이트`는 전년도 12월의 계산된 잔여를 현재 연도 `월=0` 행에 함께 갱신
- 음수 잔여도 그대로 다음 달로 이월
- 월별 실제예산은 `할당 예산 + 전월이월`이며, 잔여 또는 초과 금액은 다음 달에 그대로 자동 이월한다.

## 투자 / 에너지

두 탭은 v1에서 조회 전용입니다.

규칙:

- 구조가 예상과 다르면 앱 전체를 깨뜨리지 않는다.
- 사용자에게 구조 확인 필요 상태를 보여준다.
- 거래 입력/수정/삭제 기능과 분리한다.

## Validation checklist

로그인 후 최소 검증 항목:

- Spreadsheet 접근 가능
- `앱설정` 존재
- `schemaVersion === 1`
- `year` 일치
- `0`~`12` 탭 존재
- `통장`, `카테고리`, `예산그룹`, `예산월별` 존재
- 연결된 이전/다음 연도 정보 무결성 확인

## Non-goals

v1에서 자동 수행하지 않는 작업:

- 새 Spreadsheet 자동 생성
- 원본 수식 전체 재작성
- 실시간 감시
- 오프라인 write queue
- 외부 금융기관 연동
